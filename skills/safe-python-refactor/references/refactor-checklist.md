# 重构检查表

## 修改前

- 写清楚本次重构要改善的结构问题，以及明确不改变的行为。
- 记录公共函数、类、方法的签名和可观察副作用。
- 搜索定义的调用方、导入方、测试和配置引用，不能只看单个文件。
- 先运行最小相关测试，确认基线本身是否通过。

## 修改中

- 一次只处理一个重构目标，功能新增和缺陷修复应拆开。
- 优先保持模块路径、名称、参数默认值、返回值和异常类型不变。
- 若必须改变接口，提供迁移层或兼容包装，并把破坏性变化显式列出。
- 不以大范围格式化掩盖真正的逻辑修改。

## 修改后

- 使用 `analyze_python_api_change` 比较公共 API 与导入变化。
- 分别执行语法检查、最小相关测试和完整回归测试。
- 查看补丁边界，确认没有意外文件和无关修改。
- 交付报告必须包含证据、残余风险和回退方式。
