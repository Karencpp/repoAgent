# 失败案例：旧上下文补丁覆盖新代码

## 现象

Agent 读取某文件并生成完整替换内容。在补丁真正应用前，用户已经修改了同一个文件。如果只按路径写入，Agent 会把用户的新改动静默覆盖。

## 根因

模型生成阶段和写入阶段之间存在时间窗口，文件路径相同不代表文件版本相同。这是典型的 lost update。

## 当前处理

读取文件时记录内容 SHA-256，CandidatePatch 把它作为 `expected_sha256`。应用前重新读取工作副本文件：

```text
actual_sha256 == expected_sha256 → 可以写入
actual_sha256 != expected_sha256 → 整个补丁冲突，零文件写入
```

多文件补丁会先校验所有文件，再写第一份内容，因此第二个文件冲突不会留下第一个文件的半补丁。

## 局限

哈希只能发现内容变化，不能自动合并。冲突后需要重新读取、重新生成补丁，或未来增加显式三方合并和人工确认。

## 面试结论

LLM 的上下文具有版本，写操作必须验证读取时的前置条件，不能把旧 Prompt 中的文件内容当成当前事实。
