# 失败案例：重规划后覆盖旧计划

## 现象

Replan 直接把 `state.plan` 替换成新对象。任务最终成功，但 Trace 无法回答：原计划哪里错了、哪些步骤被保留、为什么新增了验证步骤。

## 根因

“当前状态”和“审计历史”被当成同一个概念。路由确实只需要最新计划，但调试、恢复和面试复盘需要看到状态如何变化。

## 当前处理

- `plan` 保存当前生效计划；
- `plan_history` 使用 reducer 追加每版计划；
- `evaluation_history` 保存每次拒绝和最终通过；
- `reflection_history` 保存失败原因和修正策略；
- `step_results` 保存每次尝试，不删除失败记录。

## 为什么不把所有内容写进 messages

消息可以作为展示材料，却缺少稳定字段和版本关系。结构化历史才能精确比较计划步骤、评估问题和预算变化，并支持后续 checkpoint。

## 面试结论

可观测性不是打印几行日志，而是保存足以重建状态迁移的结构化事实。
