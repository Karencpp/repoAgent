# 失败案例：把工作副本误认为进程沙箱

## 现象

pytest 在候选副本中运行，于是系统宣称目标项目无法影响真实仓库或系统。但测试代码仍可使用绝对路径、读取环境变量、访问网络，甚至定位并修改真实仓库。

## 根因

工作副本只改变了默认 cwd 和 RepoAgent 工具的路径边界，没有改变 Python 进程的操作系统权限。文件位置隔离与进程能力隔离是两个层级。

## 当前处理

- 默认不允许执行项目代码；
- 只有 CandidateEvaluationConfig 显式授权后才运行 pytest；
- pytest 使用参数数组、固定工作目录、超时和输出限制；
- 项目代码仍被视为受信或由用户明确授权的代码；
- 文档不把普通副本描述成安全沙箱。

## 真正处理不可信代码需要

- 容器或受限操作系统账户；
- 只挂载候选副本；
- 禁止或限制网络；
- CPU、内存、进程数和时间配额；
- 环境变量最小化；
- 结果目录和出站数据控制。

## 面试结论

CandidateWorkspace 防止 Agent 的正常写工具误改真实仓库，但不能约束被执行项目代码的全部系统调用。
