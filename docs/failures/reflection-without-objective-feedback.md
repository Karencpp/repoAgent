# 失败案例：没有客观反馈就触发 Reflection

## 现象

模型输出不理想后，系统直接把原回答再发给同一个模型，要求“反思并改进”。模型往往只是换一种措辞，或者在没有新证据的情况下生成更自信的结论。

## 根因

Reflection 没有引入信息增量。它既没有失败测试、编译错误、缺失 Evidence，也没有计划假设冲突，因此无法判断到底应该改实现、改参数还是改计划。

## 当前处理

Reflection 只能由 Evaluator 的 rejected 结果触发，其输入包含：

- 用户目标；
- 当前计划；
- 全部步骤执行结果；
- Evaluation summary、issues 和 evidence。

输出必须区分失败原因、纠正动作和 `should_replan`。程序再根据这个布尔值选择局部 Retry 或 Replan，并限制反思次数。

## 面试结论

Reflection 的价值来自“外部反馈 + 状态修正”，不是让模型无条件多生成一次。没有新证据的自我批评通常只是昂贵的改写。
