# 失败案例：把 Skill 的 allowed-tools 当成执行授权

## 现象

一个 pytest 诊断 Skill 声明了 `run_pytest`。当前 Workflow 步骤只授权读取代码，但 Agent 仍然执行了目标项目测试。

## 根因

- 把 Skill 当成能力提供者；
- 认为可信 Skill 的声明可以覆盖当前任务授权；
- 只在提示词里告诉模型“谨慎使用”，没有本地白名单；
- 工具暴露阶段和真正分发阶段使用了不同权限。

## 当前处理

激活时对已注册工具、当前步骤白名单和 Skill 上限求交集。模型只能看到交集中的工具，Tool Registry 调用时再次校验相同集合。Skill 的 `required-tools` 只检查宿主是否安装了必要能力，不会替当前步骤授权或自动提权。

## 面试结论

Skill 解决的是“会不会按正确步骤做”，Tool 和授权系统解决的是“能不能做”。流程知识不能成为权限来源。
