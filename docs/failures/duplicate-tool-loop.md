# 失败案例：模型重复调用同一工具

## 现象

模型拿到搜索结果后仍用相同参数再次搜索，Observation 没有新增信息，却持续消耗 token、工具时间和调用费用。

## 根因

- 模型没有正确利用 Observation；
- Prompt 指令互相冲突；
- 工具返回被截断但模型没有改变查询范围；
- Runtime 只依赖模型自行决定结束。

## 为什么仅限制迭代数不够

最大迭代数能保证最终停止，但无法尽早识别无进展。假设预算是八轮，完全相同调用可能浪费七轮才结束。

## 当前处理

Host 将工具名和规范化 JSON 参数排序序列化，再计算稳定指纹。调用执行前检查该指纹出现次数，默认第二次完全相同的调用直接以 `duplicate_call_stopped` 结束，因此重复调用不会再次产生副作用。

## 为什么不自动把结果缓存后继续

缓存可以避免真实执行，但模型若持续请求相同调用，循环仍没有进展。当前最小 Runtime 选择明确停止，把问题暴露给外层 Reflection 或重新规划。

## 局限

完全相同检测无法识别大小写变化、参数顺序外的语义等价查询或交替调用形成的循环。未来可加入观察增量、状态版本和语义循环检测；写操作还必须结合幂等键和仓库 revision。

## 面试结论

停止条件是 Agent Runtime 的确定性职责，不能只在 Prompt 中要求模型“不要重复”。
