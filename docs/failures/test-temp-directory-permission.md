# Failure card：测试临时目录权限假设错误

## 发生了什么

模块测试最初使用 `tempfile.TemporaryDirectory()`。Python 在 Windows 用户临时目录创建测试目录，但当前受控执行环境只允许写工作区，所有需要创建仓库文件的用例都返回 `PermissionError`。

将 `TemporaryDirectory(dir=workspace)` 指向项目内部后，`tempfile` 创建的子目录权限仍与当前沙箱不兼容。最终改为在项目的 `.test-tmp` 下显式创建随机 case 目录，并在测试结束后清理。

## 为什么这不是业务代码失败

所有用例在相同的 fixture 创建步骤失败，甚至“没有选择必须报错”这个不依赖仓库内容的测试也只在 teardown 失败。故障集中在测试基础设施，而不是 ProjectContext 分支。

## 面试价值

这是“外部状态与执行环境也是 Agent/测试系统的一部分”的例子：

- 不要看到大量失败就直接归因于核心逻辑；
- 先找第一个共同失败点；
- 区分业务错误、权限错误和环境错误；
- 临时目录、cwd、环境变量都属于隐式依赖，应显式控制。

## 修复后的证据

改用工作区内显式 case 目录后，16 个业务测试全部通过，说明原失败来自测试环境假设。
