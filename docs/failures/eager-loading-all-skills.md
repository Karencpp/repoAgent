# 失败案例：启动时把所有 Skill 正文塞进 Prompt

## 现象

系统安装了几十个 Skill。每次任务开始都加载全部正文和参考资料，导致上下文占用明显增加，pytest 诊断任务还受到重构、文档生成和发布流程指令干扰。

## 根因

- 混淆 Skill 发现与 Skill 激活；
- 没有渐进披露；
- description 没有承担路由摘要作用；
- 参考资料没有按需加载；
- 认为更多规程一定带来更好结果。

## 当前处理

启动扫描只读取 name、description 和少量扩展元数据；路由选中后才读正文；资源必须被正文引用或元数据声明，并在真正需要时按路径读取。Context Builder 仍对激活正文执行 token 预算校验。

## 面试结论

Skill 的价值不只是复用 Prompt，还包括控制“什么时候把哪一段流程知识交给模型”。渐进披露同时优化 token、注意力和指令冲突。
