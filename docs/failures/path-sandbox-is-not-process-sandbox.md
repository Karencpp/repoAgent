# Failure card：把路径沙箱误认为代码执行沙箱

## 错误假设

“pytest 的 cwd 已限制在 repo_root，target 也在仓库内，所以运行测试是安全的。”

## 为什么错误

cwd 只决定相对路径基准，不能限制目标代码：

- 读取用户目录和环境变量；
- 写入仓库外路径；
- 发起网络请求；
- 启动新的子进程；
- 消耗大量 CPU、内存或磁盘。

`shell=False` 防止 Shell 解释命令字符串，但同样不能限制被启动的 Python 程序行为。

## 当前防护

- pytest 默认关闭；
- 需要上层显式授予代码执行权限；
- 参数由程序构造；
- 固定 cwd；
- 设置超时和输出上限；
- target 必须位于 repo_root。

## 当前没有解决

- OS 文件权限隔离；
- 网络隔离；
- CPU、内存和进程数量配额；
- 目标依赖和插件供应链风险。

## 更强方案

需要执行不可信仓库时，应使用临时工作副本，并在容器、虚拟机或受限系统账户中运行；只读挂载不需要修改的目录，限制网络和资源，并在结束后销毁执行环境。

## 面试表达

> 路径沙箱控制的是工具显式访问范围，进程沙箱控制的是被执行代码的系统能力。两者处在不同安全层，不能互相替代。
